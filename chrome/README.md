# Brave Legacy UI (standalone)

The user interface of the **old Brave desktop browser** ([`browser-laptop`](https://github.com/brave/browser-laptop),
Brave 0.27.3), which ran on **Muon** (a now-dead Electron fork) — extracted so it renders in a plain
Chromium browser with no Muon, no main process, and no native modules.

It's a memorial and a reusable base: the chrome (tab strip, omnibox, toolbars, panels) and the `about:`
pages are real React 15 + Immutable.js + Aphrodite/LESS components, driven here by mock state instead of
Muon IPC. The web-content area (Muon's `<webview>`) is replaced by a standard `<iframe>`.

## Run it

Requires Node (an emsdk-bundled Node 22 works; the scripts set `--openssl-legacy-provider` for webpack 3).

```bash
npm install
npm run watch        # webpack-dev-server on http://localhost:8080
```

Then open:

- **http://localhost:8080/gallery.html** — index of everything
- **http://localhost:8080/index.html** — the classic browser chrome shell
- **http://localhost:8080/about-styles.html** — the component style-guide gallery (best first look)
- `about-preferences.html`, `about-newtab.html`, `about-bookmarks.html`, `about-history.html`, …

`npm run build` produces a production bundle in `public/gen/` (static, serve `public/` anywhere).

## Poke around

- **`harness/mockState/windowState.js`** — the open tabs/frames of the shell. Add a frame, flip
  `isPrivate`, change a `title` or `location`, change `activeFrameKey`. Hot-reload shows it.
- **`harness/mockState/appState.js`** — global state: bookmarks (bookmarks toolbar), settings, tabs,
  new-tab data. Unspecified settings fall back to the original `appConfig` defaults.
- The UI components are the originals under `app/renderer/components/**` and `js/about/**` — edit and watch.

## How the Muon coupling was removed

Four narrow seams (everything else is untouched original source):

1. **`harness/muonShim.js`** — defines the globals the UI expects: `chrome` (which is also the `electron`
   module, via webpack `externals`), `muon`, and `process` (with `type: 'renderer'` so the Flux dispatcher
   runs locally instead of over IPC). Prepended to every webpack entry. Modeled on the repo's own
   `test/unit/lib/fakeElectron.js`.
2. **`harness/localBoot.js`** — replaces `js/entry.js`: seeds `appStoreRenderer` + `windowStore` from the
   fixtures and mounts `<Window/>`. No IPC bootstrap.
3. **`harness/mockState/*`** — the Immutable fixtures (schema per `browser-laptop/docs/state.md`).
4. **`app/renderer/components/frame/guestInstanceRenderer.js`** — the one component that drove a Muon
   `<webview>`; rewritten to render an `<iframe>` (http(s) loads directly; `about:*` maps to the local
   extracted host page, e.g. `about:newtab` → `/about-newtab.html`).

`ipcRenderer.sendSync('translations')` is answered from **`harness/translations.js`** (generated from the
en-US `.properties` by `harness/buildTranslations.js`). HTML hosts are generated by `harness/buildHtml.js`.
Native / main-process-only / torrent modules the UI transitively references are aliased to an empty stub
in `webpack.config.js`.

## What this is not

Only the **UI shell** is revived. Real browsing, shields/ad-block, ledger/payments, sync, tor, and
downloads were main-process features — they appear as static mock state, not live behavior. The `<iframe>`
loads sites that permit framing; it's a stand-in for the Muon `<webview>`, and the natural slot to graft a
real engine onto later. The pristine source of truth remains the sibling `browser-laptop/` checkout.

## Regenerating artifacts

```bash
node harness/buildTranslations.js   # harness/translations.js  (after editing locales)
node harness/buildHtml.js           # public/*.html
```
